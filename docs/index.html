Web API 设计：从需求到 OpenAPI

这套教程整理自 Arnaud Lauret 的《The Design of Web APIs》（第 2 版，Manning）。 它讲的不是「怎么写代码实现一个 API」，而是在写代码之前的那件事： 消费者看到的接口应该长什么样，才能做对的事、好用、安全、高效，并且经得起修改。

为什么要学「设计」

你一定用过让人抓狂的 API：字段名像密码、同一个概念在两个接口里叫两个名字、报错只有一句 Bad Request、升级之后程序莫名其妙崩溃。 这些问题很少是实现写得差造成的，根源几乎都在接口的设计上。

教程地图

整套教程按四个步骤（先做什么、后做什么）和四个层次（每次只关注一类问题）展开。 先用最朴素的方式做出一个「做对了事」的设计，再一层一层地把它打磨好。

关于代码示例

原书专注于设计，没有一行实现代码。为了让你把设计决定和日常编码对上号，这套教程在每一章都补充了示例代码， 并且同时提供 Python、TypeScript 和 Java 三个版本。点击代码块上方的标签切换语言，你的选择会被记住并应用到所有章节。 

from fastapi import FastAPI, HTTPException

app = FastAPI()

@app.get("/products/{product_id}")
def get_product(product_id: str):
    product = catalog.find(product_id)
    if product is None:
        raise HTTPException(404, f"Product {product_id} doesn't exist")
    return product

import { Hono } from "hono";

const app = new Hono();

app.get("/products/:productId", (c) => {
  const productId = c.req.param("productId");
  const product = catalog.find(productId);
  if (!product) {
    return c.json({ detail: `Product ${productId} doesn't exist` }, 404);
  }
  return c.json(product);
});

@RestController
public class ProductController {

    @GetMapping("/products/{productId}")
    public Product getProduct(@PathVariable String productId) {
        return catalog.find(productId).orElseThrow(() ->
            new ResponseStatusException(HttpStatus.NOT_FOUND,
                "Product " + productId + " doesn't exist"));
    }
}

ⓘ 代码是为了说明设计

示例代码聚焦于「设计如何体现在代码里」，省略了导入语句、数据访问层等与主题无关的部分（catalog、store、accounts 这类名字代表你自己的数据层），不一定能原样运行。 OpenAPI、JSON Schema 和 Spectral 的示例则与本仓库各章目录下的清单文件相对应，可以直接贴进编辑器或在本地运行。

怎么用这套教程

  • 按顺序读。后面的章节建立在前面的概念和例子之上。第 1 章是全局地图，第 2–7 章是地基，不要跳过。
  • 先看图。每一章都有大量示意图，很多概念看图比读文字快。页面右下角的按钮可以切换深色/浅色。
  • 做练习。每章末尾有「动手练习」，点开「参考答案」之前先自己想一想。原书练习的 OpenAPI 文件在仓库的各章目录和 Appendix - Solutions to Exercises 里。
  • 边学边用。挑一个你正在用或正在做的 API，每学一章就拿它对照一遍。

💡 一句话总结

如果只记住一件事：API 是给别人用的接口。先弄清他们要做什么，再从他们的角度去设计它的样子 —— 而不是把你的数据库、你的业务规则、你的系统架构原样端出去。 这套教程剩下的全部内容，都是这句话在不同层面上的展开。
